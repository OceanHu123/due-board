# Deploy DueBoard on Render

Goal: get a URL like `https://due-board.onrender.com` you can bookmark and open anytime (even when your computer is off).
**No custom domain needed** — just use the free `*.onrender.com` subdomain, same as GitHub Pages' `*.github.io`.

> Formerly **Usyd Due** — if deploying an older version, paths/names may still use `usyd-due-web` etc.

---

## 0. Prerequisites

- [ ] GitHub account
- [ ] This repo pushed to GitHub (step 1)
- [ ] [Render](https://render.com) account (can sign in with GitHub)

Local reminders (launchd) and the web app can coexist — the web app is for "open the board anytime".

## 2. Generate a Fernet key (save it)

```sh
cd ~/Projects/due-board
uv run python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

Copy the entire output — you'll paste it into Render's `TOKEN_FERNET_KEY`.

---

## 3. Create services via Blueprint

> **Free tier note:** Render Free has no Background Worker, and its free Postgres expires after 30 days. The `render.yaml` therefore creates **only the Web service**; the database is external (Neon). The board relies on clicking "Refresh" on the web page.

1. Go to [https://dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
2. Connect GitHub, select the `due-board` repo
3. Render reads [`render.yaml`](../render.yaml) and creates:
   - **Web**: `due-board`
4. Create the external database first (section 7), then fill environment variables (section 4) → **Apply**

If a previous Blueprint attempt failed: on the Blueprint page click **Manual sync** (or delete the failed Web service and re-Apply) to pull the latest `render.yaml`.

After deploy, the Web service page shows:

`https://due-board-xxxx.onrender.com`

**Bookmark this URL.**

### If deploy fails

Open **due-board → Logs**, common causes:

| Log clue | Fix |
|----------|-----|
| database / SSL / connection | Code auto-adds `sslmode=require` for Render; pull latest code and redeploy |
| health check failed | Wait for cold start; verify `healthCheckPath` is `/healthz` |
| TOKEN_FERNET_KEY / SECRET_KEY | Add them in Environment, then **Clear build cache & deploy** |

## 4. Environment variables

In **due-board** → Environment:

| Variable | Value | Required? |
|----------|-------|-----------|
| `BASE_URL` | Optional; used as fallback. Auto-detected from Render headers. | Recommended |
| `SECRET_KEY` | Auto-generated by Blueprint, or any long random string | Yes |
| `TOKEN_FERNET_KEY` | The Fernet key from step 2 | Yes |
| `DATABASE_URL` | Your external Postgres connection string (Neon). See section 7. | Yes (manual) |
| `GITHUB_URL` | Your GitHub repo URL (footer link) | No |

### How to sign in

**No email needed:** Open the site → Settings → paste your Canvas / Ed API tokens → Save → click Refresh on the board. The board is no-auth (single-user), so no login flow is required.

## 6. Free tier caveats

- **Web sleeps**: after inactivity, the next visit may take **30–60s** cold start — normal.
- **Render free Postgres expires 30 days after creation** (then a 14-day grace period, then Render deletes it with all data — no backups). This repo therefore does **not** create a Render Postgres; `DATABASE_URL` points at an always-free external database. See section 7.
- After code changes: `git push`, Render auto-deploys (if webhook is connected).

---

## 7. Migrating off Render Postgres

Render's free Postgres is not permanent. This project uses **Neon** instead — free with no expiry, 0.5 GB storage, compute scales to zero when idle. The connection string format is identical, so **no code change is needed**.

> Keep the same `TOKEN_FERNET_KEY` throughout. Canvas/Ed tokens are stored Fernet-encrypted; importing the old rows under a *different* key makes them undecryptable and you would have to paste new tokens.

### 7.1 Create the Neon database

1. Sign up at <https://neon.tech> (GitHub sign-in, no credit card) → **New Project**
2. Pick a region near your Render region, then copy the **connection string**. Use the pooled `-pooler` host — this app opens short-lived connections.

### 7.2 Copy the rows across

No `pg_dump` / `psql` needed — [`scripts/migrate_db.py`](../scripts/migrate_db.py) does the copy with the `psycopg` driver the project already depends on:

```sh
# SOURCE = Render Dashboard → due-board-db → Connect → ✱External✱ Database URL
uv run --extra postgres python scripts/migrate_db.py \
  "postgresql://…render.com/db?sslmode=require" \
  "postgresql://…-pooler…neon.tech/neondb?sslmode=require"
```

The script:

- creates the target schema from the app's own models, so it matches what the app expects
- copies only columns present on both sides (safe if the source is older)
- inserts parents before children (foreign keys stay satisfied)
- **resets each id sequence** — without this the next insert collides on the primary key
- refuses to write into a target that already has rows unless you pass `--force`

If you prefer the standard tools, `pg_dump … --no-owner --no-privileges` + `psql -f` works equally well. (On macOS without Homebrew those aren't installed; the script above avoids that detour.)

### 7.3 Point Render at Neon

1. Render Dashboard → **due-board** → **Environment**
2. Edit `DATABASE_URL` → paste the Neon connection string → **Save**
3. Render redeploys automatically. If it does not: **Manual Deploy → Deploy latest commit**

[`web/config.py`](../web/config.py) rewrites bare `postgresql://` URLs to `postgresql+psycopg://` for you, and Neon connection strings already include `sslmode=require`.

### 7.4 Verify, then clean up

1. Open the board → **Settings** should still show your Canvas/Ed tokens as saved
2. Click **Refresh dues** → items should load
3. Only after that, delete the old Render Postgres in the dashboard. Blueprint sync never auto-deletes resources, so it simply stays until you remove it.
4. If you used `pg_dump` instead of the script, delete the dump file once you are satisfied — it contains your encrypted tokens.

## 9. FAQ

**Q: Do I need to buy a domain?**
A: No. Use `*.onrender.com`.

**Q: Why can't I host this on GitHub Pages?**
A: GitHub Pages is for static sites. This is a **FastAPI + database** app that needs a backend-capable platform like Render.

**Q: It loads slowly?**
A: Free Web cold start after sleep. Click and wait; or upgrade to paid always-on later.

**Q: Are tokens safe?**
A: Stored encrypted (Fernet) in the cloud DB. Only your Render account has access; revoke tokens anytime in Canvas/Ed.

**Q: I'm at a different university (UNSW / Monash / Custom)?**
A: Go to **Settings → Institution** and switch — default Canvas / Ed URLs adjust automatically.
